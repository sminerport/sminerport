# sminerport profile repo

GitHub profile README. `main` is the default branch and is what the profile renders; `dev` mirrors it.

## Branches and merging
- `main` and `dev` reject direct pushes (ruleset: PR required, no deletion, no force-push, no bypass). Work on a branch, then `gh pr create --fill --base main` and `gh pr merge --merge --delete-branch`.
- `output` is an orphan branch rewritten by workflows via `scripts/publish_output.sh`. Never check it out or push to it by hand; the README embeds raw URLs from it.
- After merging: `git switch main && git pull --ff-only && git fetch --prune`.

## README
- The list between `<!-- BLOG-POST-LIST:START -->` and `END` is bot-managed by `update-blog.yml`; don't edit it by hand.
- Theme-aware images use `<picture>` with a `prefers-color-scheme: dark` source; keep both variants when changing the graph.
- Avoid third-party widget servers (Vercel/Heroku stats, trophies, Spotify); they're what broke before. Prefer files generated by workflows.

## Workflows
- `update-blog.yml` hourly: commits to `bot/blog-posts`, opens and merges a PR. A no-change run deletes the branch.
- `now-playing.yml` every 30 min: `scripts/now_playing.py` renders Last.fm to `now-playing.svg` on `output`. Needs secret `LASTFM_API_KEY`.
- `profile-3d.yml` nightly: 3D graph to `output/profile-3d-contrib/`. Uses secret `PAT_3D` if valid, else `GITHUB_TOKEN`. Private-repo detail in the radar/language charts needs a classic token with `repo` AND `read:user`; `repo` alone returns public repos only. Action is pinned to a release on purpose.
- Anything writing to `output` must use `concurrency: group: output-branch`.
- Don't add `push` triggers to workflows that commit; bot pushes would loop or trip the ruleset.

## Testing
- `python3 scripts/now_playing.py --sample --out /tmp/card.svg` (add `--idle` for the not-playing state); no API key needed.
- `python3 -c "import yaml,sys; [yaml.safe_load(open(f)) for f in sys.argv[1:]]" .github/workflows/*.yml` before pushing workflow edits.
- Preview the README as GitHub renders it: `gh api markdown --input body.json` (mode `gfm`) wrapped in github-markdown-css.
- `gh run list --workflow=<file>.yml` and `gh run view <id> --log-failed` to verify a run.

## Gotchas
- The `gh` CLI token reports public-only contribution counts from GraphQL even with `repo` scope; don't use it to judge activity.
- Scheduled workflows are disabled after 60 days without commits; the blog action's keepalive handles that.
